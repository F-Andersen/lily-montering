# Ручне тестування fiksitt

Дата: 2026-10-04, Europe/Kiev. Вихідні часи DB зберігаються в UTC.
Тестування локальне, ізольований Docker project `fiksitt-seo-qa`:
сайт `http://127.0.0.1:18082`, Mailpit `http://127.0.0.1:18026`.
Основний preview 18081, його адміністратор і production не змінювалися.
Нижче ручні UI-перевірки через Codex in-app Chromium browser, не автотести.
Фактичні viewport: 1280 px desktop та 375 px mobile emulation.

## Виправлення під час тестування

`script.js`: після успішного reset знімається aria-invalid, а під час вводу
перевіряється лише змінене поле, не всі порожні поля одразу. При зміні країни
оновлюється перевірка вже введеного телефону. Публічний JS cache version = 4.

SMTP переведений на PHPMailer 7.1.1, додано TLS/config/header validation,
номер заявки, час UTC, посилання на адмінку. DB-first поведінка збережена.
Retry для ненадісланих заявок та тестовий лист в settings захищені session,
POST, CSRF, rate limits; GET не надсилає пошту. MySQL named lock захищає
від одночасної початкової доставки/повтору. Schema migration не потрібна.

## Автоматизоване доповнення

Ці перевірки НЕ називаються ручними:
- `tests/qa.cjs`: 28 груп PASS, 50 responsive views (10 x 5 ширин).
- `tests/extra.cjs`: 5 груп PASS, включно з no-JS формою, CSP та cookie flags.
- `tests/seo-admin.cjs`: 7 груп PASS, 20 responsive admin views.
- `tests/mail-notifications.cjs`: 6 груп PASS: auth/CSRF/POST-only, test send
  rate limit, concurrent lock, repeat/spam guards, UTF-8/headers/link, TLS
  та відмова header injection. Лише локальний Mailpit, зовнішніх листів немає.
- `tests/admin-media.cjs`: PASS, 375/947/1440, photo precedence та незмінність DB.

Перший основний прогін зупинився на тестовому settings payload: він надсилав
seo_indexable=0 як начебто ввімкнений checkbox. Тест виправлено відповідно
до HTML-поведінки: невибраний checkbox не надсилається. Наступний прогін PASS.
Це не послаблення перевірок production-indexing.

## Межі перевірки

Не перевірено реальну Gmail delivery/SMTP auth/TLS handshake: немає пароля
застосунку. Mailpit acceptance не означає delivery до Gmail.
Не тестовано production після deploy, HTTPS на реальному домені, DNS/SPF/
DKIM/DMARC, реальні iOS/Safari/Firefox або фізичний мобільний пристрій.
Це не pentest, навантажувальний тест чи гарантія відсутності будь-яких багів.
Реальні паролі не змінювалися. Сторінку Konto оглянуто, ручна зміна пароля
не виконувалася; сценарії зміни пароля описані в окремих попередніх QA.
Скасування confirm-діалогу через цей браузерний API не підтверджене.
Видалення CRUD/файлів, pagination/CSRF/XSS та DB-only/mail-only/dual-failure
додатково покриті автоматично.
